Each one below is a concrete situation, the steps and the prompt to type in the [AI Assistant](/docs/ai/ai-assistant), and what to expect back — not just a general capability.

## Create a Job Using a Briefing Template

**Overview**

Create a new job using the [Document Agent](/docs/ai/agents/document-agent) and automatically generate its brief based on the briefing template configured for the selected Job Type.

**Scenario**

A project manager needs to create a new campaign job. By providing the campaign details to the Document Agent, the system creates the job and generates a brief following the structure defined in the Job Type's briefing template.

**Example prompt**

```
Create a new job for the client Nike with the following details:

- Job Type: Digital Campaign
- Job Title: Nike Summer Campaign 2026
- Priority: High
- Description: Develop a digital campaign to promote Nike's summer collection.

Generate the job brief using the briefing template configured for this Job Type.
```

**Expected outcome**

- A new job is created with the specified information.
- The correct Job Type is selected.
- The job brief follows the briefing template configured for that Job Type.
- The generated brief includes the relevant information provided in the prompt.

## Check burn without a dashboard

**Situation:** You want to know, right now, whether a retainer or project is burning more hours than it was contracted for, without opening a workspace first.

1. Open the [AI Assistant](/docs/ai/ai-assistant) panel.
2. Ask it directly, naming the client or project:

```
Compare contracted vs. logged hours on the Northwind retainer this month.
```

3. The assistant resolves the client or project you named and answers from one of your tenant's own data extraction reports — the same figures behind your dashboards — rendered as a chart with a table beside it.

:::note
Answering from your reports is a capability an agent is granted, not one tied to a single named agent — see [Tools · Your data](/docs/ai/ai-tools#your-data). If the agent you're on says it can't run the query, ask whoever set up your AI which one has this switched on.
:::

## Cover several accounts, not just one

**Situation:** You manage several client accounts and want each one to have its own status page, without building them one by one through a form.

1. Say which client the portal is for and what it should show — status, burn, risks, open requests.
2. Once the first one is done, ask for the next client's portal in the same conversation:

```
Build a status portal for Northwind. Then build the same one for Acme, and for Delta.
```

3. Each portal is generated separately, reading that client's own live data through their own permissions. See [Client Portals](/docs/ai/ai-portals) for how a portal is published, and what to check before handing the link to a client.

## See what's critical across your accounts

**Situation:** You want one view that surfaces what needs attention across every account you manage, instead of checking each client's workspace in turn.

1. Open the AI Assistant, select **Workspace Agent**, and open (or start) the workspace you want this on.
2. Describe the dashboard you want:

```
Build me a dashboard of critical activity across all my accounts — overruns, risks and pending approvals.
```

3. Review the proposal before applying it — nothing is saved until you do. See [Workspace Agent](/docs/ai/agents/workspace-agent) for how a workspace change is built and applied.

## Ask about a client's projects and tasks

**Situation:** You need a quick, accurate answer about what's open on a client's account, without opening every job to check.

1. Open the AI Assistant and select **Document Agent**.
2. Ask, naming the client:

```
What tasks are open on the Northwind account right now?
```

3. The assistant searches across that client's jobs, deliverables and other documents and answers directly; click a result to open it. See [Document Agent](/docs/ai/agents/document-agent) for the full list of document types it can search.
